Handle an IPv6 loopback host without taking the process down, require the fetch destination the loopback server documents, and stop a blank `AI_OAUTH_SDK_HOME` writing credentials into the working directory.

`loopbackReceiver()` parsed each request against `http://${bindHost}`. For `loopbackReceiver({ host: '::1' })` that base is `http://::1`, which is not a URL, and the `ERR_INVALID_URL` it throws has nothing above it to catch: `node:http` lets an exception out of the request listener reach the default `uncaughtException` handler, so a single `GET` to the bound port exited the process with status 1. The `Sec-Fetch-*` gate runs first, so a subresource still got its `403`, but a top-level navigation — the shape the provider's own redirect has — went straight through to the parse. Nothing in the module is reading the authority back off that URL, only `pathname` and `search`, so the base is now the constant `http://localhost` and the whole class is gone. The default host `127.0.0.1` was never affected.

`buildLoopbackRedirectUri()` had the same unbracketed interpolation and produced `http://::1:34835/callback` for an IPv6 `loopbackHost` or `redirectHost` — a redirect URI the authorization server is handed verbatim and that `new URL()` refuses. An IPv6 literal is now bracketed (RFC 3986 §3.2.2), and one already written as `[::1]` is left alone. That covers `defaultRedirectUri()`, `manualReceiver()`'s paste fallback and the CLI's `--port` path, which all build their URI through it. None of the bundled providers names an IPv6 host, so this only reaches callers who asked for one.

The loopback server's fetch-metadata check faulted `Sec-Fetch-Dest` only when the header was present, so `Sec-Fetch-Site: cross-site` plus `Sec-Fetch-Mode: navigate` and no destination was accepted — where SECURITY.md states that both `navigate` and `document` are required. There is no known exploit in the gap: every engine that emits `Sec-Fetch-Site` emits `Sec-Fetch-Dest` alongside it, and an attacker forging headers can simply send `Dest: document` or none at all. It is now the documented check. The deliberate exemption is untouched, because it is keyed on `Sec-Fetch-Site` and sits outside the destination test: a client that sends no fetch metadata — curl, undici, anything non-browser — and a typed-in URL's `Sec-Fetch-Site: none` both still pass, as does a genuine `navigate`/`document` redirect. Only the site-and-mode-without-destination shape changes.

`defaultAuthDir()` used `??`, which does not fall back on the empty string. A Dockerfile's `ENV AI_OAUTH_SDK_HOME=` or an `export AI_OAUTH_SDK_HOME="$SOMETHING_UNSET"` in CI leaves the variable present and blank, and the credential path then became relative: refresh tokens written to `./auth.json` in whatever the working directory happened to be, typically a git working tree or a Docker build context. Blank is now treated as unset, matching the `--auth-dir` flag the docs call equivalent and which was already guarded this way. The file is still written `0600`; nothing else about the storage adapter changes.
