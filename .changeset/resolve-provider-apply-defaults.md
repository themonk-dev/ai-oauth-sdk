Apply `defineProvider()`'s defaults to an inline descriptor, constrain the host the Copilot exchange names, and redact the OpenAI device flow's poll fields.

**`resolveProvider()` took an inline `ProviderConfig` verbatim, so `defineProvider()`'s defaults never applied to it.** A descriptor handed in as an object rather than a built-in id came through with `usePkce` and `pkceMethod` undefined and `tokenRequest` empty, and `usePkce` undefined is falsey: the authorization URL went out with no `code_challenge` and the flow returned no `codeVerifier`. That contradicts what the security notes promise — PKCE on by default, with S256, for every redirect-based provider, with `usePkce: false` as the only opt-out — and it failed open rather than loudly.

TypeScript does not let you get there: `ProviderConfig` requires those three fields, so a descriptor written in TypeScript always states them. Everyone else can. A JavaScript consumer, or anyone assembling a descriptor from a JSON config file, produces exactly the object that silently loses PKCE, and nothing in the flow says so. The existing coverage passed a `defineProvider()` result, which only exercised the safe path.

The inline branch now runs the descriptor through `defineProvider()`. It is idempotent on every built-in — including `github-copilot`, whose deliberate `usePkce: false` is preserved, since `...input` spreads after the defaults — caller-set values still win over the defaults, and per-call `overrides` still win over both.

**The Copilot token exchange used the API host from its response without looking at it.** GitHub returns it under `endpoints.api` and it decides where every later request sends the exchanged Copilot token as a bearer credential, for that token's ~25-minute life. Any string was taken: cleartext, a non-http scheme, or something that is not a URL at all. This was not reachable — the value arrives over TLS from a hard-coded `https://api.github.com/copilot_internal/v2/token` — but it is remote input reaching the same place a discovery document's endpoints reach, and those have been checked since the discovery hardening. It now gets the same rule, https except on loopback, and an `OAuthError` naming the field and the value when it fails. It throws rather than falling back to the descriptor's `apiBaseUrl`, because quietly sending an enterprise account's token to the individual host would surface only as a puzzling 401. Every host GitHub actually names, individual or enterprise, is a public https host; a local Copilot proxy on `127.0.0.1` keeps working.

**Redaction missed the two fields OpenAI's device flow polls with.** `SECRET_PARAMS` carries `device_code` and `code`, but the pattern's `\b` anchors cannot fire inside `device_auth_id` or `user_code` — `_` is a word character — so a body containing both came back byte-for-byte unchanged and both values reached the error message. Those two are the entire body the poll POSTs, and together they are what claims the token, for the fifteen minutes the device authorization is live. The trigger is the one the redaction already exists for: a gateway echoing the request back. Both names are now listed, with a note that the list is not only the standard spellings, so the next provider-specific field is not missed. `user_code` on its own is shown to the user by design and those display paths are untouched; it is the pair in an untrusted response body that is redacted.
