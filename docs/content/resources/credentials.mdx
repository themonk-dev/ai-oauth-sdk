Every provider needs a client id, and you always name it explicitly. No provider defaults to one.
This page lists the published values so you can pass the same credential from the SDK that the CLI
uses by default.

<Callout type="warn" title="These identify the vendor's own CLI">
  Using one means presenting your application as that CLI. That is a decision only you can make,
  which is why it is an argument rather than a default. See the
  [disclaimer](/docs/resources/disclaimer).
</Callout>

## From the SDK

```ts
import { createAuthClient, ProviderId, publicClientIds, publicClientSecrets } from 'ai-oauth-sdk/node'

const claude = createAuthClient({
  provider: ProviderId.Claude,
  clientId: publicClientIds[ProviderId.Claude],
})

// Gemini is the only one that also needs a secret.
const gemini = createAuthClient({
  provider: ProviderId.Gemini,
  clientId: publicClientIds[ProviderId.Gemini],
  clientSecret: publicClientSecrets[ProviderId.Gemini],
})

// OpenRouter needs neither. The callback URL is the identifier.
const openrouter = createAuthClient({ provider: ProviderId.OpenRouter })
```

The one-shot helper takes the same options:

```ts
import { login, ProviderId, publicClientIds } from 'ai-oauth-sdk/node'

const { accessToken } = await login(ProviderId.OpenAI, { clientId: publicClientIds[ProviderId.OpenAI] })
```

## From the CLI

The CLI opts into these for you. It is an application in its own right, so it can make that choice
once on your behalf:

```bash
ai-oauth-sdk login openai   # uses publicClientIds.openai
ai-oauth-sdk login gemini   # uses the published id and secret
```

Override either per invocation:

```bash
ai-oauth-sdk login gemini --client-id '<id>.apps.googleusercontent.com' \
                          --client-secret '<secret>'
```

Prefer the environment variable for the secret. A flag is visible in `ps` and lands in shell
history:

```bash
AI_OAUTH_SDK_CLIENT_SECRET='<secret>' ai-oauth-sdk login gemini
```

The CLI never writes a client secret to the credential file. It is read fresh each invocation, so a
value that was briefly visible in `ps` does not become a durable copy on disk.

## Bringing your own

Register your own client wherever the provider offers it, and you present as yourself rather than
as someone else's CLI.

| Provider | Where |
| --- | --- |
| `gemini` | **Google Cloud console > Credentials > Create credentials > OAuth client ID > Desktop app** |
| `azure-ai` | **Entra ID > App registrations > New registration**, as a public client |
| `github-copilot` | **GitHub > Settings > Developer settings > OAuth Apps** |

Two have no self-service path for a desktop CLI, so the published id is the only one that works:

- **xAI** rejects any client it has not allowlisted, with `invalid_client` and "Unknown or disabled
  client".
- **ChatGPT** and **Claude** issue CLI clients to their own tools. There is no registration form
  for a third-party equivalent.

## Scopes

Defaults are the minimum for chat. Widen them per client:

```ts
createAuthClient({
  provider: ProviderId.Claude,
  clientId: publicClientIds[ProviderId.Claude],
  scopes: [
    'user:inference',
    'user:profile',
    'user:sessions:claude_code',
    'user:file_upload',
  ],
})
```

`claude` defaults to `user:inference`, `user:profile` and `user:sessions:claude_code`. Claude Code
additionally requests `org:create_api_key`, `user:file_upload` and `user:mcp_servers`. None is
needed to send a prompt, and `org:create_api_key` in particular lets any leaked token mint durable
organization API keys that outlive the OAuth session, so ask for it only if you want it.

On the CLI, `--scopes` takes a comma or space separated list:

```bash
ai-oauth-sdk login claude --scopes 'user:inference,user:profile,user:file_upload'
```

## If a credential stops working

Published values can be rotated by the vendor at any time, and automated secret scanning may prompt
that for Gemini's. Nothing breaks structurally. Pass your own with `--client-id` and
`--client-secret`, the environment variable, or the SDK options above. An `invalid_client` error is
the signal.
