Signing in is the easy half. This is what to do with what comes back.

## Short answer

Pass `createAuthenticatedFetch(client)` as the `fetch` option of whatever client you already use.
The Vercel AI SDK, the OpenAI SDK and the Claude SDK all accept one.

```ts
import { createOpenAI } from '@ai-sdk/openai'
import { generateText } from 'ai'
import { createAuthenticatedFetch } from '@ai-oauth-sdk/core'
import { createNodeAuthClient } from '@ai-oauth-sdk/node'

const client = createNodeAuthClient({ provider: 'openai', clientId })

const openai = createOpenAI({
  apiKey: 'unused', // the SDK insists on one; our fetch replaces it
  baseURL: client.provider.apiBaseUrl,
  fetch: createAuthenticatedFetch(client),
})

const { text } = await generateText({ model: openai.responses('gpt-5.5'), prompt: 'hi' })
```

`openai.responses`, not `openai.chat`: OpenAI's OAuth surface serves `/responses` and nothing
else. Call `fetchCodexModels(client)` for the slugs the signed-in account can actually use rather
than hardcoding one.

## Why not just pass the token

Three ways to wire it, worst to best:

| Approach | Refreshes? | Notes |
| --- | --- | --- |
| `apiKey: tokens.accessToken` | no | Captured once. Dies at expiry, mid-session. |
| `headers: { Authorization }` | no | Same problem. A static object is built once. |
| `fetch: createAuthenticatedFetch(client)` | yes | Refreshes before expiry, retries once on 401, adds the provider's headers. |

Only the third survives a long-running session, which is the whole point. A token that expires
after twenty minutes is not something you want captured in a closure.

<Callout type="warn" title="The managed token wins by default">
  `createAuthenticatedFetch` used to let an `Authorization` header set by the caller take
  precedence. That is reasonable when you are calling it directly. It is wrong when the caller is an
  SDK that sets `Authorization` from its own `apiKey` before handing over, which the AI SDK does
  even when `apiKey` is empty or omitted. All three variants above sent a placeholder while the
  library refreshed the real token and attached it to nothing. Since `0.1.2` the managed token
  wins. Pass `respectCallerAuthorization: true` for the old behaviour.
</Callout>

## What the fetch does

| Option | Type | Description |
| --- | --- | --- |
| `fetch` | `FetchLike` | Underlying fetch. Defaults to `globalThis.fetch`. |
| `retryOnUnauthorized` | `boolean` | Force a refresh and retry once when the API answers 401. Defaults to `true`. |
| `baseUrl` | `string` | Prefix for relative URLs. Wins over both the provider's `apiBaseUrl` and any host a credential exchange names. |
| `headers` | `Record<string, string>` | Merged into every request, beating anything the provider supplies, so this is where you override a default like Copilot's `Editor-Version`. A header set on the request itself still wins over both. |
| `respectCallerAuthorization` | `boolean` | Let a caller-set Authorization header survive. Defaults to `false`. |

The 401 retry matters more than it looks. A token can be revoked, or rotated by another process,
well before its nominal expiry, in which case the local clock says "still valid" and only the 401
reveals otherwise.

Requests with a streaming body are never retried, because the stream is consumed by the first
attempt and cannot be replayed. Those return the 401 as-is rather than throwing, since turning a
recoverable failure into a hard one would be worse.

## Per-provider gotchas

The token alone is not always enough.

**OpenAI.** A ChatGPT-subscription token does not work against `api.openai.com`, which wants an
API key and answers this token with `403 Missing scopes: api.model.read`. It works against
`chatgpt.com/backend-api/codex`, which is where `apiBaseUrl` points. Four things beyond the bearer
are needed there and the descriptor supplies all of them, including a rewritten `/responses` body:
that endpoint runs stateless and answers a request missing its reasoning configuration with an
empty stream rather than an error. See the [provider page](/docs/providers/openai) for what goes
into it. For an API-key account, whose token carries no `https://api.openai.com/auth` claim, pass
`baseUrl: 'https://api.openai.com/v1'`.

**GitHub Copilot.** The stored `ghu_` token is not what the API takes. It wants a short-lived
Copilot token obtained by exchanging that one, and the same response names the host to send it to,
which differs for enterprise accounts. `createAuthenticatedFetch` runs the exchange, caches it, and
re-runs it on a 401. It also names an editor, which Copilot requires. Pass
`headers: { 'Editor-Version': 'my-cli/1.0' }` to identify as yourself. The exchanged token lives
about 25 minutes, which is the other reason a captured token will not do.

**Claude.** OAuth bearers need `anthropic-beta: oauth-2025-04-20` alongside `anthropic-version`.
The descriptor emits both through `apiHeaders`, and `createAuthenticatedFetch` attaches them. A
hand-rolled `headers` object will not.

**OpenRouter.** The flow returns a normal API key rather than an OAuth token, so there is nothing
to refresh and `apiKey:` is genuinely fine here.

## Anything that takes a fetch

```ts
import OpenAI from 'openai'

const openai = new OpenAI({
  apiKey: 'unused',
  fetch: createAuthenticatedFetch(client),
})
```

Or no SDK at all:

```ts
const api = createAuthenticatedFetch(client)
const models = await api('/models').then((response) => response.json())
```

Relative paths resolve against the provider's `apiBaseUrl`, which is why that call has no host in
it.

## When the SDK will not take a fetch

Build it per call, so each one gets a fresh token:

```ts
async function openai() {
  return new OpenAI({ apiKey: await client.getAccessToken() })
}

const response = await (await openai()).chat.completions.create({
  model: 'gpt-5',
  messages: [{ role: 'user', content: 'hi' }],
})
```

`getAccessToken()` is cheap when the token is still valid. It only touches the network inside the
expiry window, and concurrent callers share one refresh.
