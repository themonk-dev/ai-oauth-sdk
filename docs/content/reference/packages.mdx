Ten packages, all released together at the same version.

| Package | Purpose |
| --- | --- |
| [`ai-oauth-sdk`](https://www.npmjs.com/package/ai-oauth-sdk) | Umbrella and CDN build. Start here. |
| `@ai-oauth-sdk/core` | Zero-dependency engine: PKCE, registry, exchange, refresh, providers |
| `@ai-oauth-sdk/cli` | `ai-oauth-sdk login ...` for the terminal |
| `@ai-oauth-sdk/node` | Loopback server, file storage, browser launcher |
| `@ai-oauth-sdk/browser` | Popup and redirect receivers, web storage |
| `@ai-oauth-sdk/react` | `useAuth` and `AuthProvider` |
| `@ai-oauth-sdk/vue` | `useAuth` composable |
| `@ai-oauth-sdk/svelte` | `createAuth` store |
| `@ai-oauth-sdk/solid` | `createAuth` primitive |
| `@ai-oauth-sdk/react-native` | Deep link and auth session receivers, SecureStore |

## The umbrella

```ts
import { createAuthClient } from 'ai-oauth-sdk/core'
import { login } from 'ai-oauth-sdk/node'
import { popupReceiver } from 'ai-oauth-sdk/browser'
import { useAuth } from 'ai-oauth-sdk/react'
import { useAuth } from 'ai-oauth-sdk/vue'
import { createAuth } from 'ai-oauth-sdk/svelte'
import { createAuth } from 'ai-oauth-sdk/solid'
import { secureStoreAdapter } from 'ai-oauth-sdk/react-native'
```

`ai-oauth-sdk` itself re-exports the core, so a bare `import { createAuthClient } from
'ai-oauth-sdk'` works too.

It depends on all eight adapters, which is the tradeoff: one install and eight subpaths, versus
installing only what you need. The framework bindings are declared as optional peers, so installing
the umbrella in a Node project does not demand React.

## Every package re-exports the core

```ts
import { OAuthError, publicClientIds } from '@ai-oauth-sdk/node'
```

That works, and so does the equivalent from `browser`, `react`, `vue`, `svelte`, `solid` and
`react-native`. It saves a second import line from the same family, and it means a page of your code
that only touches one adapter only names one package.

## Formats

Every package ships ESM and CJS with types, through an `exports` map. The build is verified
separately from the tests: unit tests import source, so a broken `exports` map would not fail them.
`pnpm verify:exports` resolves every published subpath through Node's real resolver against the
built output.

## Runtime requirements

Node 22 or later for the Node adapter and the CLI. The core needs `fetch` and either
`crypto.getRandomValues` or an injected `CryptoAdapter`, which covers every current browser, Deno,
Bun, Workers, and React Native with the bundled fallback.

## Versioning

Changesets, with every package held at the same version through a `fixed` group. A patch to the
core bumps all ten. That is deliberate: the adapters are only useful against a matching core, and
the alternative is a version matrix nobody wants to reason about.

Releases are published through npm trusted publishing with OIDC, from a job that installs nothing
and runs no project code. The build happens in a job with no credentials at all, and the two hand
over a directory of tarballs.
