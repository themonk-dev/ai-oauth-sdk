The API is small, and almost all of it is one class plus four interfaces. Knowing which is which
makes the rest of this section easier to navigate, because the pages are split along that line.

## One class, four interfaces

`AuthClient` is the only object that does anything. Everything else is a shape: either data it hands
you, or a seam you implement so it can work in your runtime.

| Name | Kind | What it is | Page |
| --- | --- | --- | --- |
| `AuthClient` | class | The orchestrator. Every method that runs a flow or touches a token is on it. | [AuthClient](/reference/auth-client) |
| `TokenSet` | interface | The data a completed flow gives back. You read it, you do not implement it. | [TokenSet](/reference/tokens) |
| `AuthStorage` | interface | Where tokens and pending flows are written. **You can implement this.** | [Storage](/reference/storage) |
| `CallbackReceiver` | interface | How the authorization code gets back into your process. **You can implement this.** | [Receivers](/reference/receivers) |
| `ProviderConfig` | interface | The description of a provider. **You can implement this.** | [Custom providers](/providers/custom) |
| `OAuthError` | class | Every failure this library raises, with a `code` to branch on. | [Errors](/reference/errors) |

The two marked interfaces you are most likely to write yourself are `AuthStorage` and
`CallbackReceiver`. `ProviderConfig` you normally build with `defineProvider()` rather than by hand.

## Where behaviour lives

This is the distinction worth being clear about, because it is the one that reads as duplication if
you skim.

**Methods live on [AuthClient](/reference/auth-client).** `getAccessToken()`, `refresh()`,
`revoke()` and `logout()` are documented there, once, including how refresh deduplicates across
concurrent callers.

**Shapes live on their own page.** [TokenSet](/reference/tokens) describes the fields a token set
carries and how expiry is represented. It does not restate the methods.

So if you are asking "what can I call", start at AuthClient. If you are asking "what did I get
back", start at TokenSet.

## Standalone functions

Not everything hangs off the class. These are imported directly from `@ai-oauth-sdk/core`.

| Function | What it does |
| --- | --- |
| `createAuthClient(options)` | Builds an `AuthClient`. The adapters ship preconfigured variants. |
| `createAuthenticatedFetch(client)` | A `fetch` that attaches a valid token and retries once on 401. See [using the token](/recipes/ai-sdk). |
| `createAuthStore({ client })` | The observable wrapper every UI binding is built on. See [frameworks](/frameworks). |
| `defineProvider(input)` | Fills in the defaults for a provider descriptor. |
| `providerFromDiscovery(issuer, input)` | Builds a descriptor from an OIDC discovery document. |
| `fetchUserInfo(client)` | Calls the provider's userinfo endpoint, where it declares one. |
| `revokeToken(input)` | RFC 7009 revocation, if you want it without a client. |
| `isOAuthError(value)` | Narrows an unknown error. Survives two copies of the package on disk. |
| `decodeJwtPayload(token)` | Decodes, never verifies. |
| `redactSecrets(value)` | Scrubs credentials before you log something. |
