```ts
import { createAuthClient } from '@ai-oauth-sdk/core'

const client = createAuthClient({ provider: 'openai', clientId })
```

`createAuthClient` and `new AuthClient` are the same thing. The adapters ship preconfigured
variants: `createNodeAuthClient` adds file storage and `node:crypto`, `createBrowserAuthClient`
adds `sessionStorage`.

## Running a flow

### login(options)

Runs an entire login through a receiver and returns the tokens. Stores them on the way through.

```ts
const tokens = await client.login({
  receiver: loopbackReceiver(),
  timeoutMs: 120_000,
  signal: controller.signal,
  scopes: ['openid', 'profile'],
  metadata: { returnTo: '/settings' },
  openUrl: (url) => shell.openExternal(url),
})
```

`state` is compared in constant time, and a callback carrying no `state` is rejected rather than
waved through. Only providers with `echoesState: false` are exempt.

### deviceLogin(options)

RFC 8628, unless the provider supplies its own implementation.

```ts
const tokens = await client.deviceLogin({
  onCode: (device) => console.log(device.verificationUri, device.userCode),
  signal,
  scopes,
})
```

`onCode` is awaited, so you can render a QR code before polling starts.

### createAuthorization(options)

Mints `state`, derives a PKCE pair, persists both, and returns the URL to send the user to.

```ts
const { url, state, redirectUri, codeVerifier } = await client.createAuthorization({
  redirectUri,
  scopes,
  extraParams,
  metadata,
})
```

### completeAuthorization(input)

Finishes the flow for a `state` and returns its tokens. Accepts either an explicit `code` and
`state` pair or a raw `callbackUrl`, so an HTTP handler can pass `req.url` straight through.

```ts
await client.completeAuthorization({ callbackUrl: req.url })
await client.completeAuthorization({ code, state })
```

Consumes the pending record. Also notifies anyone blocked in `waitForAuthorization` for the same
`state`, including on failure.

### waitForAuthorization(state, options)

Blocks until the flow for `state` completes. A result that arrives before anyone waits is buffered,
and several waiters on one `state` all get served.

```ts
const tokens = await client.waitForAuthorization(state, { timeoutMs: 120_000, signal })
```

### getPendingAuthorization(state)

Reads a pending record without consuming it. This is how you get `metadata` back before completing.

### cancelAuthorization(state)

Deletes the pending record and rejects any waiters with an `aborted` error.

## Tokens

### getAccessToken(options)

The everyday call. Returns a valid access token, refreshing transparently when it is inside the
expiry window.

```ts
await client.getAccessToken()
await client.getAccessToken({ forceRefresh: true })
```

Throws `refresh_failed` when there are no stored tokens at all, with a message telling you to run
the login flow.

### refresh(options)

Forces a refresh. Deduped across concurrent callers, so ten parallel calls waking to an expired
token fire one request.

Before refreshing it re-reads storage, because another process may have refreshed since. Two CLI
windows racing is ordinary, and with providers that rotate refresh tokens the loser's token is
already dead, so a usable stored token is taken instead.

<Callout title="Joining an in-flight refresh means joining its cancellation">
  A later caller's `signal` is not attached to a refresh that is already running, and the first
  caller's abort fails everyone waiting on it. That is the trade for never issuing two refreshes at
  once.
</Callout>

### getTokens() and setTokens(tokens)

Read and write the stored `TokenSet` directly. `setTokens` is what you want when migrating
credentials in from somewhere else.

### isAuthenticated()

True when a token exists and has not passed the renewal window. It does not touch the network.

### authorizationHeader()

`"Bearer <token>"`, refreshing first if needed. The token is fetched before the type is read,
because a refresh replaces the whole token set.

### revoke(options)

RFC 7009, where the provider supports it. Revoking the refresh token is what ends the session.

This talks to the provider and nothing else. The local token stays in storage, so
`isAuthenticated()` keeps returning true until you clear it.

### logout(options)

Clears stored tokens for this provider and account.

```ts
await client.logout() // local only
await client.logout({ revoke: true }) // tell the provider too, where supported
```

Local state is cleared either way. A failed revocation must not leave the user apparently still
signed in.

## Properties

`client.provider` is the resolved `ProviderConfig`, after your overrides have been merged. That is
where `apiBaseUrl`, the redirect spec and the scopes actually in use can be read.
