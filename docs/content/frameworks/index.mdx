React, Vue, Svelte and Solid each get a package, and each package is thin. The loading flags, the
error handling, the cancellation, and the restore-on-start all live in `createAuthStore()` in the
core. A binding maps that onto the framework's reactivity and stops there.

That is why the four APIs look so alike. It is not a style choice, it is the same object underneath.

```ts
import { createAuthStore } from '@ai-oauth-sdk/core'

const store = createAuthStore({ client, receiver })

store.subscribe((state) => render(state))
await store.restore()
await store.login()
```

`subscribe` follows the Svelte store contract: it calls the listener immediately with the current
state and returns an unsubscribe function. That contract happens to suit React, Vue and Solid too,
so nothing needed a bespoke shape.

## The state

Every binding exposes the same four values.

| Value | Type | Description |
| --- | --- | --- |
| `tokens` | `TokenSet | undefined` | The current session, or undefined when signed out. |
| `isAuthenticated` | `boolean` | Whether tokens is set. Not a check against expiry. |
| `isLoading` | `boolean` | True while a login, refresh or restore is in flight. |
| `error` | `Error | undefined` | The last failure. An aborted login is not treated as one. |

And the same five actions: `login`, `logout`, `refresh`, `getAccessToken`, `cancel`.

## Choosing a receiver

The bindings supply no receiver of their own, because the right one depends on your app rather than
your framework. In a browser that means one of the two from `@ai-oauth-sdk/browser`:

```ts
import { popupReceiver } from '@ai-oauth-sdk/browser'

useAuth({ provider: 'openai', clientId, receiver: popupReceiver() })
```

A full-page redirect does not fit `login()` at all, because the page unloads before anything can
resolve. Use `startRedirectLogin` and `handleRedirectCallback` directly for that, and let the
binding own only the state after the fact.

## Notifications are suppressed when nothing moved

The store compares before it emits, so a binding that maps state straight onto reactive primitives
does not re-render for free. A second `login()` supersedes the first rather than racing it, and an
abort is treated as a user action rather than an error worth putting in front of them.
