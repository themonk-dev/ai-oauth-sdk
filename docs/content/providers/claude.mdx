const client = createNodeAuthClient({

| Setting | Value |
| --- | --- |
| Authorization | `https://claude.ai/oauth/authorize` |
| Token | `https://platform.claude.com/v1/oauth/token` |
| Redirect | loopback, any port, path `/callback` |
| Hosted callback | `https://platform.claude.com/oauth/code/callback` |
| Browser redirect | also accepts an arbitrary HTTPS redirect — verified live, undocumented |
| Popup opener | severed by an enforced `Cross-Origin-Opener-Policy: same-origin` |
| Scopes | `user:inference`, `user:profile`, `user:sessions:claude_code` |
| API base | `https://api.anthropic.com/v1` |

## Two redirect modes

Claude registers loopback URIs with the port component ignored, as RFC 8252 asks, so any port
works. That is the default and nothing is pasted.

It also publishes a hosted page that displays a code, which is the right answer over SSH. The
`defaultReceiver` in the Node adapter switches to it automatically when the machine looks headless,
because sending a remote box's `localhost` URI to a browser on your laptop produces a redirect
nothing can receive, and there is no device flow here to fall back to.

```bash
ai-oauth-sdk login claude --paste
```

## The pasted value is not a URL

The hosted page hands back `CODE#STATE` as one opaque string. The descriptor's `parseCallback`
handles that, and also accepts a full redirect URL, because the same provider supports both modes.

## Scopes are deliberately narrow

The default is enough to chat and nothing more:

- `user:inference` is the Messages API
- `user:profile` is the identity `whoami` reads
- `user:sessions:claude_code` is the session this grant belongs to

Claude Code additionally requests `org:create_api_key`, `user:file_upload` and `user:mcp_servers`.
None is needed to send a prompt, and `org:create_api_key` in particular turns a leaked token into
durable organization credentials that outlive the OAuth session. Ask for them explicitly when you
want them:

```ts
import { claude, ProviderId, publicClientIds } from '@ai-oauth-sdk/core'

createAuthClient({
  provider: ProviderId.Claude,
  clientId: publicClientIds[ProviderId.Claude],
  scopes: [...claude.scopes, 'org:create_api_key', 'user:file_upload'],
})
```

## The token request

The endpoint accepts both form and JSON bodies. This library sends the RFC 6749 form encoding;
other clients send JSON. Claude also accepts `state` on the code exchange, which most providers
reject, so the descriptor sets `includeState`.

## Calling the API

OAuth bearers need `anthropic-beta: oauth-2025-04-20` alongside `anthropic-version`. The descriptor
emits both through `apiHeaders`, so `createAuthenticatedFetch` attaches them:

```ts
const api = createAuthenticatedFetch(client)
const response = await api('/messages', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    model: 'claude-opus-4-5',
    max_tokens: 256,
    messages: [{ role: 'user', content: 'hi' }],
  }),
})
```

A hand-rolled `headers` object will not carry the beta flag, and the request will be refused.

## No device flow

Claude does not offer one. On a machine with no browser at all, the hosted callback page plus
paste is the path, and it works because the user can open that URL on any device.

## In a browser

The descriptor's shape — `mode: 'loopback'` plus a hosted paste fallback — understates what the
registered client actually accepts. `https://claude.ai/oauth/authorize` opened in a signed-in
browser, with the published Claude Code client id and `redirect_uri=https://chat.themonk.dev/callback`,
rendered the consent screen rather than a `redirect_uri_mismatch`. That means a browser app deployed
to an HTTPS origin still gets a popup rather than falling back to paste, which is not true of every
built-in — see [browser selection](/docs/flows/browser-selection) for the full comparison.

The popup itself carries a separate hazard. `claude.ai` serves its authorization page with an
enforced `Cross-Origin-Opener-Policy: same-origin`, which detaches the popup from its opener the
moment it navigates there. A receiver that polls the popup's `closed` property to detect
cancellation — the default in this library — reports a working sign-in as cancelled about a second
after the popup opens. See [the COOP hazard](/docs/flows/popup-and-redirect#the-coop-hazard).
