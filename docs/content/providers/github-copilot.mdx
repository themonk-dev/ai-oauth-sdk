```ts
import { createNodeAuthClient, publicClientIds } from '@ai-oauth-sdk/node'

const client = createNodeAuthClient({
  provider: 'github-copilot',
  clientId: publicClientIds['github-copilot'],
})

const tokens = await client.deviceLogin({
  onCode: ({ verificationUri, userCode }) =>
    console.log(`Open ${verificationUri} and enter ${userCode}`),
})
```

## Device flow only

GitHub's OAuth app for Copilot has no registered redirect URI, so the authorization-code flow is
unavailable. `client.login()` has nothing to redirect to. Use `deviceLogin()`.

GitHub's device flow does not use PKCE, which is why the descriptor sets `usePkce: false`. That is
GitHub's design rather than an omission here: the device grant has no redirect to intercept, and
the device code is delivered over a back channel.

## The token you get is not a Copilot token

The `ghu_` token GitHub returns is a GitHub token. Copilot's API does not accept it directly:

```ts
import { exchangeForCopilotToken } from '@ai-oauth-sdk/core'

const copilot = await exchangeForCopilotToken(tokens)

copilot.token // short-lived Copilot API token
copilot.expiresAt // about 30 minutes out
copilot.raw // endpoints and feature flags GitHub returns alongside
```

Fetch that per session rather than storing it. The durable credential is the GitHub token in your
`TokenSet`; the Copilot token is derived from it and expires quickly enough that persisting it buys
nothing.

## The API host is data

`copilot.raw` carries the endpoints GitHub wants this account to use. Individual accounts get
`api.individual.githubcopilot.com`; enterprise accounts get a host of their own. That means the
base URL is a property of the credential rather than a constant on the descriptor, and hard-coding
`api.githubcopilot.com` will work for some users and not others.

```ts
const endpoints = copilot.raw.endpoints as { api?: string } | undefined
const baseUrl = endpoints?.api ?? 'https://api.githubcopilot.com'
```

## Refresh is mandatory

A 25 to 30 minute session token is short enough that any long-running process will cross it. Do not
capture the token in a closure. Re-exchange when it expires, and let
[`createAuthenticatedFetch`](/recipes/ai-sdk) handle the GitHub token underneath.

## Two client ids exist

VS Code's Copilot extension and the Copilot CLI publish different ids. `publicClientIds['github-copilot']`
is the VS Code one. Both work for the device flow; they differ in what GitHub attributes the usage
to.

## Registering your own

GitHub, Developer settings, OAuth Apps. Enable the device flow on the app, and request the `copilot`
scope. Whether a self-registered app can reach the Copilot API depends on the account's entitlement
rather than on the OAuth app, so test it before shipping.
