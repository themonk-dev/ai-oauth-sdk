<Callout type="warn" title="Experimental">
  This descriptor is marked `experimental`. Its endpoints come from xAI's OIDC discovery document
  and its client id from the grok-cli source, neither of which xAI documents as a public interface.
  Expect it to move.
</Callout>

```ts
import { createNodeAuthClient, publicClientIds } from '@ai-oauth-sdk/node'

const client = createNodeAuthClient({
  provider: 'xai',
  clientId: publicClientIds.xai,
})
```

## The client id is not really optional

xAI rejects any client it has not allowlisted, with `invalid_client` and "Unknown or disabled
client". There is no self-service registration for a desktop CLI, so `publicClientIds.xai` is
effectively the only value that works. You still pass it explicitly, because the library never picks
a vendor identity for you.

## Both flows work

Unusually, xAI supports loopback and the device grant, and its device grant is ordinary RFC 8628:

```ts
const tokens = await client.deviceLogin({ onCode })
```

That makes it the easiest of the built-ins to use from a container.

## The port is fixed

`56121` on `127.0.0.1` specifically, not `localhost`. Some providers treat the two as different
registered URIs, so the descriptor pins the host as well as the port.

## Endpoints from discovery

If they move, you have two options without waiting for a release. Override them:

```ts
import { resolveProvider, xai } from '@ai-oauth-sdk/core'

createAuthClient({
  provider: resolveProvider(xai, { tokenUrl: 'https://auth.x.ai/oauth2/v2/token' }),
  clientId,
})
```

Or rebuild the descriptor from discovery at startup:

```ts
import { providerFromDiscovery } from '@ai-oauth-sdk/core'

const provider = await providerFromDiscovery('https://auth.x.ai', {
  id: 'xai',
  label: 'Grok (xAI)',
  clientId: publicClientIds.xai,
  redirect: { mode: 'loopback', loopbackPort: 56121, loopbackHost: '127.0.0.1' },
})
```

The second is the more durable choice if you are shipping something long-lived.
