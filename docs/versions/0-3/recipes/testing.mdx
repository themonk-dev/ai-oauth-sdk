Mocking `AuthClient` tests your mock. Point the real client at a fake authorization server instead,
and the PKCE derivation, the `state` comparison, the exchange and the refresh all get exercised.

`defineProvider` makes that three lines:

```ts
import { createAuthClient, defineProvider, memoryStorage } from '@ai-oauth-sdk/core'

const testProvider = (baseUrl: string) =>
  defineProvider({
    id: 'test',
    label: 'Test',
    clientId: 'test-client',
    authorizationUrl: `${baseUrl}/authorize`,
    tokenUrl: `${baseUrl}/token`,
    scopes: ['openid'],
    redirect: { mode: 'loopback', loopbackPort: 0 },
  })

const client = createAuthClient({
  provider: testProvider(fakeServer.url),
  redirectUri: 'http://localhost/callback',
  storage: memoryStorage(),
})
```

## What a good fake does

This repository's own `fakeAuthServer` is a reasonable model. It:

- validates PKCE by recomputing the S256 challenge from the verifier, so a broken verifier fails
  the suite rather than only failing in production
- rotates refresh tokens, which is what catches code that assumes the old one keeps working
- serves a protected endpoint that rejects stale tokens, so the 401 retry path is real
- can run the device grant

Making it fail on demand is what tests your error handling:

```ts
const failing = await startFakeAuthServer({ failWith: 'invalid_grant' })
```

## Testing without a network

The receiver is the seam. A test receiver resolves immediately with whatever code you want:

```ts
import type { CallbackReceiver } from '@ai-oauth-sdk/core'

function scriptedReceiver(result: { code: string; state?: string }): CallbackReceiver {
  return {
    id: 'scripted',
    async start() {
      return {
        redirectUri: 'http://localhost/callback',
        async present() {},
        async wait() {
          return result
        },
        async close() {},
      }
    },
  }
}
```

Note that `login()` compares `result.state` against the value it issued, so a scripted receiver has
to echo the right one or the login fails with `state_mismatch`. That is the check working. To get
the issued value, use `createAuthorization()` directly rather than `login()`.

## Injecting fetch

Every network call goes through the `fetch` you pass, so you can assert on requests without a
server at all:

```ts
const calls: Array<[string, RequestInit | undefined]> = []

const client = createAuthClient({
  provider: testProvider('https://auth.example.com'),
  storage: memoryStorage(),
  fetch: async (url, init) => {
    calls.push([url, init])

    return new Response(JSON.stringify({ access_token: 'at', token_type: 'Bearer' }), {
      headers: { 'Content-Type': 'application/json' },
    })
  },
})
```

That is also how you test `createAuthenticatedFetch` behaviour: answer 401 once, then 200, and
assert the request was replayed with a fresh token.

## Expiry

`TokenSet.expiresAt` is absolute epoch milliseconds, so testing the refresh window means writing a
token rather than waiting:

```ts
await client.setTokens({
  accessToken: 'expired',
  refreshToken: 'r',
  expiresAt: Date.now() - 1000,
  tokenType: 'Bearer',
  provider: 'test',
  raw: {},
})

// getAccessToken() now refreshes rather than returning the stale one.
const fresh = await client.getAccessToken()
```

`expirySkewMs` defaults to 60 seconds, so a token expiring in 30 seconds is already treated as
stale. Set it explicitly in tests that care about the boundary.
